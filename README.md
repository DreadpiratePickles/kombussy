# kombussy

Convert fonts between **TTF/OTF**, **WOFF** and **WOFF2**, entirely in the browser
or from the command line. Safe Rust compiled to WebAssembly — no Emscripten, no
server, no upload.

A rebuild of [bashi/kombu](https://github.com/bashi/kombu) (2018–2021), which
did the same job with a C++ codebase behind an Emscripten toolchain and webpack 4.

## What it does

| | Read | Write |
|---|---|---|
| `sfnt` (TTF, OTF/CFF) | ✅ | ✅ |
| WOFF 1.0 | ✅ | ✅ |
| WOFF 2.0, untransformed | ✅ | ✅ |
| WOFF 2.0, `glyf`/`loca` transformed | ✅ | ❌ — see [Limitations](#limitations) |

Everything decodes into one `Font` type and encodes back out of it, so every
conversion is `decode → Font → encode` with no per-format special cases.

## Use it

### Web

```bash
make web && cd web && npm run preview
```

Drop a font in. The result downloads, and the panel labelled **Proof** loads the
*converted* bytes back through the CSS Font Loading API — so the page shows you a
browser accepting the output, not just a success message.

### Command line

```bash
make cli
./target/release/kombussy --to woff2 MyFont.ttf --output MyFont.woff2
./target/release/kombussy --info MyFont.woff2
```

Reads stdin and writes stdout when paths are omitted, so it pipes.

### As a crate

```rust
use kombussy_core::{convert, Format};

let woff2 = convert(&ttf_bytes, Format::Woff2)?;
```

## How it is verified

Self-consistency is not evidence: an encoder and decoder that share a
misreading of the spec will round-trip perfectly and still emit broken fonts.
So the corpus is generated by [fontTools](https://github.com/fonttools/fonttools)
and checked in **both** directions.

```bash
make test      # 30 Rust tests
make interop   # fontTools reads our output, and we read fontTools' output
```

- `make test` covers the container codecs, `UIntBase128` edge cases, the
  normative WOFF2 tag table, and a malformed-input suite that feeds every
  truncated prefix and single-byte corruption of each fixture through the
  decoder to prove it never panics.
- `make interop` converts the fixtures with the real CLI, reopens the results in
  fontTools, and compares compiled table bytes, glyph outlines (via a
  decomposing pen) and composite-component structure.

Two differences are deliberately masked when comparing tables, and only two:
`head.checkSumAdjustment`, which is derived from the finished file, and
`head.flags` bit 11, which WOFF2 producers are *required* to set. Everything
else is compared byte for byte.

## Limitations

**The encoder does not apply the `glyf` transform.** WOFF2 lets a producer
either transform `glyf`/`loca` or declare transform version 3, the null
transform. Both are conformant; kombussy writes the latter and leans on brotli.
The decoder *does* reconstruct transformed tables, so files from Google Fonts and
every other real-world source open correctly.

The cost is measurable and small on this corpus:

| File | Size |
|---|---|
| source `synthetic.ttf` | 1152 B |
| kombussy `.woff` | 844 B |
| kombussy `.woff2` (null transform) | 504 B |
| fontTools `.woff2` (glyf transform) | 492 B |

2.4% larger here. The gap widens on glyph-heavy fonts, since that is exactly
what the transform targets. Implementing the encode side is the main open item.

Also not yet supported: TrueType Collections (`.ttc`), WOFF extended metadata
and private blocks (they are dropped, not corrupted), and font subsetting.

The wasm module is **1012 KB, 484 KB gzipped**, dominated by brotli's encoder
tables. The app shell on top of it is 10.5 KB of JavaScript.

## Layout

```
crates/kombussy-core/   codec: sfnt, woff1, woff2, glyf transform. No I/O, no wasm.
crates/kombussy-cli/    native binary, zero dependencies beyond the core
crates/kombussy-wasm/   wasm-bindgen surface
web/                    Vite + TypeScript app
fixtures/               synthetic corpus and the fontTools cross-checks
```

`kombussy-core` is `#![forbid(unsafe_code)]` and denies `unwrap`, `expect`,
`panic` and raw indexing, so malformed input has to travel through the typed
`FontError` path.

## Build requirements

- Rust 1.82+ with the `wasm32-unknown-unknown` target
- `wasm-pack` and `binaryen` for the wasm build
- Node 20+ for the web app
- `uv` for the fixture and interop scripts (fontTools is fetched on demand)
