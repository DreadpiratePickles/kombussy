Convert fonts between **TTF/OTF**, **WOFF** and **WOFF2** — entirely in the browser or from the command line. Safe Rust compiled to WebAssembly: no Emscripten, no server, no "upload your font to our totally trustworthy converter dot biz." Everything round-trips through one `Font` type, and every byte this thing emits is cross-checked by making fontTools read it back. If fontTools chokes, I lose. It doesn't choke.

This is a rebuild of [bashi/kombu](https://github.com/bashi/kombu) (2018–2021), which did the same job with a C++ codebase strapped behind an Emscripten toolchain and webpack 4. A moment of silence for webpack 4. Moving on.

## What it does
| | Read | Write |
|---|---|---|
| `sfnt` (TTF, OTF/CFF) | ✅ | ✅ |
| WOFF 1.0 | ✅ | ✅ |
| WOFF 2.0, untransformed | ✅ | ✅ |
| WOFF 2.0, `glyf`/`loca` transformed | ✅ | ❌ — see [Limitations](#limitations) |

Everything decodes into one `Font` type and encodes back out of it. Every conversion is `decode → Font → encode` — no per-format special cases, no spaghetti matrix of N² converters, no exceptions to feel clever about.

## Use it
### Web
```bash
make web && cd web && npm run preview
```
Drop a font in. The result downloads — and the panel labelled **Proof** loads the *converted* bytes back through the CSS Font Loading API. That's a real browser rendering your actual output, not a green checkmark powered by hope.

### Command line
```bash
make cli
./target/release/kombussy --to woff2 MyFont.ttf --output MyFont.woff2
./target/release/kombussy --info MyFont.woff2
```
Omit the paths and it reads stdin, writes stdout, and pipes. Because obviously.

### As a crate
```rust
use kombussy_core::{convert, Format};

let woff2 = convert(&ttf_bytes, Format::Woff2)?;
```

## The receipts
Self-consistency is not evidence — an encoder and decoder that share the same misreading of the spec will round-trip *flawlessly* and still emit broken fonts, smiling the whole time. So the corpus is generated by [fontTools](https://github.com/fonttools/fonttools) and the checking runs in **both** directions. Neutral referee, hostile cross-examination.
```bash
make test      # 30 Rust tests
make interop   # fontTools reads our output, and we read fontTools' output
```
- `make test` covers the container codecs, `UIntBase128` edge cases, the normative WOFF2 tag table, and a malformed-input suite that feeds **every truncated prefix and single-byte corruption of each fixture** through the decoder to prove it never panics. Yes, every one. Paranoia is a feature.
- `make interop` converts the fixtures with the real CLI, reopens the results in fontTools, and compares compiled table bytes, glyph outlines (via a decomposing pen), and composite-component structure.

Exactly two differences are masked in the table comparison, and I can defend both: `head.checkSumAdjustment`, which is derived from the finished file, and `head.flags` bit 11, which WOFF2 producers are *required* to set. Everything else is compared byte for byte. No third exception. Don't ask.

## Limitations
**The encoder does not apply the `glyf` transform** — and here's the honest version of that. WOFF2 lets a producer either transform `glyf`/`loca` or declare transform version 3, the null transform. Both are fully conformant; kombussy writes the latter and lets brotli do the squeezing. The decoder, meanwhile, *does* reconstruct transformed tables — so files from Google Fonts and every other real-world source open correctly. I read your fancy transform just fine; I simply decline to write one. Yet.

The cost of that decision, measured instead of hand-waved:
| File | Size |
|---|---|
| source `synthetic.ttf` | 1152 B |
| kombussy `.woff` | 844 B |
| kombussy `.woff2` (null transform) | 504 B |
| fontTools `.woff2` (glyf transform) | 492 B |

2.4% larger here. The gap widens on glyph-heavy fonts, since that is exactly what the transform targets. Implementing the encode side is the main open item.

Also not yet supported: TrueType Collections (`.ttc`), WOFF extended metadata and private blocks (dropped, not corrupted — there's a difference and it matters), and font subsetting.

The wasm module is **1012 KB, 484 KB gzipped**, and I'll tell you exactly who to blame: brotli's encoder tables, which dominate the binary. The app shell riding on top is a svelte 10.5 KB of JavaScript.

## The floor plan
```
crates/kombussy-core/   codec: sfnt, woff1, woff2, glyf transform. No I/O, no wasm.
crates/kombussy-cli/    native binary, zero dependencies beyond the core
crates/kombussy-wasm/   wasm-bindgen surface
web/                    Vite + TypeScript app
fixtures/               synthetic corpus and the fontTools cross-checks
```
`kombussy-core` is `#![forbid(unsafe_code)]` and denies `unwrap`, `expect`, `panic` *and* raw indexing — so malformed input has exactly one road available: the typed `FontError` path. There is no panic to find. I checked. Byte by byte, remember?

## What you need
- Rust 1.82+ with the `wasm32-unknown-unknown` target
- `wasm-pack` and `binaryen` for the wasm build
- Node 20+ for the web app
- `uv` for the fixture and interop scripts (fontTools is fetched on demand)
